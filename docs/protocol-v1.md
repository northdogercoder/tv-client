# TV control protocol v1 — normative design (2026-11-25)

This document is identical in both repositories. Server owns the wire contract; client consumes it. Changes require a coordinated PR to both repositories, a version bump for breaking changes, and fixture parity. No shared third repository or git submodule required. JSON UTF-8, snake_case, UUID strings, UTC RFC3339 times, milliseconds for playback positions, integers only. Jellyfin 100 ns ticks are converted at the client boundary. All URLs below are relative to a configured HTTPS origin. Never forward Jellyfin credentials or media to OVH. The server is optional for local Jellyfin use, required for the cloud remote and YouTube search/player bridge.

## Transport and identities
- Bind HTTP server to 127.0.0.1:8787; publish only through Tailscale Serve HTTPS. No Funnel; phone and Pi join same tailnet. Application auth still mandatory. Never trust forwarded headers as authentication. Browser exact Origin matching for mutating routes and WebSockets; no permissive CORS. No cookies on device routes; no device bearer in browser.
- Operator uses local `tv-server admin enrollment create --label living-room` to mint a 32-byte random one-use token, valid 10 min. It is shown once; Pi passes it in request body via stdin-driven enrollment CLI, never argv/history. Database stores SHA-256 digest of high-entropy token, compare constant-time where applicable; transaction consumes token once. Device bearer 32 random bytes, shown only once; hash at rest server-side, store plaintext in client 0600 file under state dir. Revocation closes sockets and invalidates grants/sessions. Rotate by explicit re-enrollment (admin revoke old device after replacement succeeds). No self-service arbitrary user registration.
- Pairing: Pi authenticated POST creates 8-digit random decimal code (leading zeros preserved), 120s TTL, one active request per device. Remote submits code within tailnet. Return a pending request with opaque 32-byte claim token and 4-digit comparison code displayed both on TV and phone. User physically accepts on TV only (not remote input); reject or timeout otherwise. Phone polls claim token in POST body every 2s for 120s max; once approved receives opaque 32-byte session as Secure HttpOnly SameSite=Strict cookie (Path=/, no Domain; 30d absolute expiry); single device scope. Poll token consumed atomically. Server issues CSRF token on session GET; require exact Origin plus X-CSRF-Token on mutations. Local admin can list/revoke remote sessions. Code attempts bounded globally, per source and per code, do not use IP alone as identity. No QR secret; QR may encode only the remote page origin/path.
- All non-health/API static operations require appropriate device bearer, remote session, or player session. Reject bad content-type, malformed/unknown fields, invalid enum/range, expired tokens; no generic command shell, arbitrary media URLs, or arbitrary target hosts. Max HTTP body 64 KiB, WS frame 32 KiB, max 10 commands/s per remote, 5 pairing attempts/min per source plus global cap, bounded queues (32 pending commands/device), request timeouts 10s. Errors JSON {"error":{"code":"invalid_request","message":"Safe explanation","request_id":"uuid"}}; HTTP 400/401/403/404/409/429/503. No credentials in logs.

## HTTP endpoints
| Method/path | Auth | Request → response |
|---|---|---|
| GET /healthz | none | 200 {"status":"ok"} (liveness only) |
| GET /readyz | none | 200 {"status":"ready"} or 503; database migration/read check |
| POST /v1/enroll | enrollment token in body | {token,label} → {device_id,device_token,protocol:1} |
| GET /v1/device/config | device | {protocol:1,features:{youtube:bool,airplay:bool,webrtc:bool},heartbeat_ms:15000} (local flags and hardware gate still authoritative) |
| POST /v1/pair/init | device | {} → {pair_id,code,expires_at} |
| POST /v1/pair/request | anonymous exact Origin | {code} → {request_id,claim_token,comparison_code,expires_at} |
| POST /v1/pair/decision | device | {request_id,accept:bool} → 204; local physical confirmation enforced by client |
| POST /v1/pair/claim | claim token body exact Origin | {claim_token} → 202 pending / 200 {device_id} + cookie / 410 expired |
| GET /v1/session | remote | {device_id,csrf_token} |
| DELETE /v1/session | remote+CSRF | 204 revoke and clear cookie |
| GET /v1/devices/{device_id}/state | matching remote | latest state or offline, no media URLs |
| POST /v1/devices/{device_id}/command | matching remote+CSRF | {command_id,action} → 202 {command_id,status:"queued"}; 409 if offline/full |
| GET /v1/youtube/search?q=...&page_token=... | device or paired remote | {items:[{video_id,title,channel_title,thumbnail_url}],next_page_token:null|string}; no keys exposed |
| POST /v1/player/ticket | device | {video_id,playback_id} → {ticket,expires_at} (one use 30s) |
| POST /v1/player/exchange | ticket body, exact Origin | {ticket} → {video_id,playback_id} + scoped Secure HttpOnly SameSite=Strict player cookie (max 4h) |
| GET /player | none | static first-party player page, no sensitive data, requires ticket exchange before loading embed |
| GET /remote | none | static mobile UI; pairing/session needed for data |
| GET /v1/ws/device | device bearer | websocket; one connection/device, newest authenticated replaces old |
| GET /v1/ws/remote | remote cookie+Origin | websocket; read-only state/ack; command via POST (optional approved cast signaling only) |
| GET /v1/ws/player | player cookie+Origin | websocket; bound to device/playback id, controls/events only |

`/v1/player/*` must be disabled if feature disabled. Player ticket passed to ephemeral browser via URL fragment (never query), remove fragment with history.replaceState immediately, POST to exchange then clear memory reference. Do not expose ticket in logs, crash reports, persistent browser profile or remote response. Process argv briefly contains ticket; local account is dedicated, token one-use and short-lived. Prefer a local controlled handoff if the spike proves it feasible. Player session revoked on stop, expiry or device disconnect after 30s grace. No browser navigation to untrusted origins except official embedded player; no remote debugging exposed.

## WebSocket messages
Envelope {"v":1,"type":"...","id":"uuid","payload":{...}}. Strict per-direction schemas; unknown type → safe error or close 1008; unsupported version close 1002. Heartbeat ping/pong every 15s, disconnect after 45s. No offline replay. `hello` device→server includes {device_id,client_version,capabilities:["jellyfin","youtube",...]} and server→device `hello_ack` {connection_id}; send state immediately then on change and every 5s during playback. State payload {device_id,seq,mode,source,item_id,title,position_ms,duration_ms,volume,paused,error_code}; seq monotonically increasing within connection, reset on new connection; mode home|browsing|loading|playing|paused|casting|standby|error; source null|jellyfin|youtube|airplay|webrtc; nullable item/title/position/duration/error; volume 0..100. Remote sees offline after heartbeat timeout, with stale state flagged. Item titles only to paired remotes; disable sharing titles option in client.

Actions tagged by `kind`: `navigate` {direction:up|down|left|right|select|back|home}; `set_paused` {paused:bool}; `seek` {position_ms:nonnegative integer}; `set_volume` {volume:0..100}; `stop` {}; `play_youtube` {video_id:11-character [A-Za-z0-9_-]}; `play_jellyfin` {item_id:opaque string 1..128, no URL}; `standby` {enabled:bool}. No `pair_accept`, no system poweroff/exec. Device validates every action against mode, local Jellyfin permissions and active playback; returns `ack` {command_id,status:applied|rejected|failed,reason:null|string}. Server sends `command` {command_id,action}; queue expiry 10s, client dedupe last 256 ids/10 min in RAM, ack timeout reported unknown, never replay automatically on reconnect. Duplicate id with same device/session returns prior status, mismatched payload → 409. Pending commands discarded on disconnect. Remote shows queued vs applied distinctly.

Player bridge: Rust creates playback_id, requests ticket, spawns browser; player sends `player_event` {playback_id,event:ready|playing|paused|ended|error|position,position_ms?,duration_ms?,error_code?}; server forwards to matching device. Device sends `player_control` {playback_id,command_id,action} (same tagged action format, only set_paused|seek|set_volume|stop); server forwards to active player; player returns `player_ack` {playback_id,command_id,status} when API reports result (unsupported controls rejected). `stop` causes device to terminate/reap browser and send `player_close` {playback_id}; late events ignored. Remote commands route via device, never directly to player. Use IFrame API, preserve controls/ads/branding; actual autoplay and seeking may be limited. If bridge unavailable, exit to launcher safely.

Pairing push events: server→device `pair_request` {request_id,comparison_code,expires_at}; server→device `pair_status` {request_id,status:pending|accepted|rejected|expired}. Phone polls claim; no unpaired WebSocket. Device may query/re-init after reconnect; expired decisions fail.

## Optional WebRTC extension (disabled by default)
Add only after core acceptance. Add POST /v1/cast/request (remote+CSRF) {device_id} → pending {cast_id}; server sends `cast_request` {cast_id} to device; locally approve (not remote navigation) via `cast_decision` {cast_id,accept}. Only approved paired remote and device exchange `cast_signal` {cast_id,kind:offer|answer|ice|end,data:string} over their authenticated sockets; cap size 32 KiB, rate, session 2h, no SDP/ICE logs, no recording. Browser offer sendonly H.264 if negotiated; Pi GStreamer recvonly. No arbitrary remote desktop control. On end, lost socket or consent revocation stop tracks and pipeline. ICE direct on LAN/tailnet first; TURN not part of default release. If added, ephemeral TURN REST credentials and restrict listener/relay range to intended networks, test both sides; never operate open relay. Screen/audio support is browser-specific; Android native MediaProjection sender deferred, Pixel Cast menu not promised.

## Compatibility
JSON fixtures in `docs/protocol-fixtures.json` are shared examples, not an exhaustive schema. Both repos must implement strict typed parsers, positive/negative tests and compare SHA256 of these two files before integration. No binary shared dependency. Contract amendments must update docs, fixtures, parser tests and versions in both repositories. Default v1 single household, multiple paired remotes but one active playback per Pi.
